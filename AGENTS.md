# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## What this is

`pen` runs AI programming agents (Claude Code, Codex, OpenCode, Pi) in a Docker container scoped to one project directory, with egress limited to a domain allowlist and owner-scoped GitHub credentials. The host CLI is a .NET 11 Native AOT binary (`cli/Pen`); the container side is `compose.yaml`, `image/` (Dockerfile + entrypoint), `proxy/` (squid + default allowlist) and `templates/` (first-run user config and home seed). See README.md for an introduction and installation, docs/usage.md for detailed user-facing behavior, and CONTRIBUTING.md for the build/test/release workflow.

## Commands

Full details in CONTRIBUTING.md. The essentials (.NET commands run from `cli/`; SDK pinned in `cli/global.json`, xunit v3 on Microsoft.Testing.Platform):

```
cd cli && dotnet build         # warnings are errors
cd cli && dotnet test          # unit tests; --filter-class Pen.Tests.CliTests / --filter-method "*Name*"
cli/install.sh                 # AOT-publish and install ~/.local/bin/pen
tests/smoke.sh                 # end-to-end checks against the *installed* pen; needs Docker
SMOKE_ONLY="7 13" tests/smoke.sh   # only those sections (the fixture setup always runs)
```

## Architecture

**Embedded resources.** `Pen.csproj` embeds `compose.yaml`, `image/**`, `proxy/**`, `templates/**` under their repo-relative paths (`Embedded.cs`). The installed binary never reads this repo, so **changes to any of those files only take effect after rebuilding/reinstalling the CLI**. Every installation, including planned Homebrew packages and release binaries, builds `pen:latest` locally from the embedded Dockerfile and supporting files; pen does not publish its own container image. `Embedded.ImageHash()` hashes `image/`; `Image.EnsureCurrent()` rebuilds `pen:latest` when the label doesn't match, so editing `image/` triggers a rebuild on next session. `pen upgrade` rebuilds locally with fresh agents.

**Flow** (`Program.cs`): `Cli.Parse` → `Config.EnsureUserConfig` (creates `~/.config/pen/` from `templates/`) → `Project.Resolve` (cwd real path; key `pen-<dir>-<hash>` of the main checkout (`RepoDir`) names volumes, project image and runtime dir, so a repo's linked worktrees share it while `Dir`/`PROJECT_DIR` stays the worktree) → command (`Session`, `AllowCommand`, `Sign`, `Reset`; `Ps` and `Prune` run before `Config`/`Project`: `Ps` lists `Sessions.RunningEverywhere`, `Prune` classifies every key with volumes or a runtime dir by its `project-dir` as live, moved, missing or unknown and removes moved/missing ones under `project.lock` exclusive). User-facing errors are `PenException` (message + exit code).

**Sessions** (`Session.cs`, `SessionDir.cs`, `SessionSignals.cs`): each session is its own compose project `<key>-<id>` with a dir under the project's runtime dir holding the generated `compose.yaml`, `session.yaml` override (`SessionCompose.Override`: mounts, dind settings, the ports service), `squid.conf`, `allowlist.txt`, `session.env`, `command`/`started`/`ports` (for `pen ps`), lock and `proxy.log`. Presence of `compose.yaml` marks a session open. Every command that resolves a project writes the main checkout's real path to the runtime dir's `project-dir` (`Session.EnsureRuntimeDir`), which `pen prune` uses to tell moved or deleted projects apart. Locking (`Sessions.TakeFor*`): sessions hold `project.lock` and their dir's `worktree-<hash(dir)>.lock` shared; `reset` takes `project.lock` exclusive; `sign` takes `project.lock` shared and the worktree lock exclusive, so it's refused only by sessions in its own dir; a dind lock allows one `--docker` session per project. Sessions whose pen died are cleaned up by the next run (`FinishDeadSessions`). Teardown must remove the agent and dind, or establish their absence with a successful daemon query, before checking Git. If this fails, the session files are retained and the command fails for retry. Signals: SIGINT/SIGQUIT go to the agent; SIGHUP/SIGTERM trigger the normal end path (`SessionSignals`). Volumes (`_home`, `_nuget`, `_dind`) are external and shared by all sessions of a project.

**Isolation**: the agent is on an `internal` network; only the squid proxy has egress. Forwarded ports (`--port`, `ports`) add a `ports` service (pen:latest running socat as `nobody`, no caps, read-only root) on `sandbox` plus a non-internal `ports` network, publishing `127.0.0.1:<p>:<p>` and relaying to the agent by container name (`compose run` gives it no service alias); `Port.Choose` checks each port on the host first (a taken `--port` is an error, a taken config port a warning; never remapped). `pen allow` rewrites the allowlists of running sessions started in its dir (all projects' with `--global`) live. The entrypoint (`image/entrypoint.sh`) runs twice: as root with minimal caps to create the user from `PEN_UID/PEN_GID`, then as the agent with all caps dropped; it copies the home seed (`~/.config/pen/home`, mounted read-only) into `$HOME`. Under rootless Docker the agent is UID 0 with no capabilities on a read-only root fs (`Docker.IsRootless`).

**Protecting the host's git** (`RepoGuard`, `RepoScan`, `GitCheck`, `GitConfigFile`): pen refuses nested repos (including a submodule with its own `.git` dir: the refusal suggests `git submodule absorbgitdirs`), symlinked `.git`, `commondir`, `.git` files that aren't validated linked worktrees (`RepoScan.ResolveWorktree`) or checkouts of known submodule repos (`RepoScan.ResolveModuleCheckout`: `gitdir:` names one, whose `core.worktree` points back), and worktrees of bare repos. In a linked worktree, the main repo's git dir (`CommonGitDir`) is mounted read-write with the same protections, plus the gitfile and the main checkout's `HEAD`/`index` read-only; the session saves the common dir (`started-with-git`) for the end check. It mounts `.git/config`, `.git/hooks`, `.pen/` and worktrees' `commondir` read-only over themselves (via `session.yaml`; `ProtectGitDir`), and the `.git/worktrees/<n>` entry of each worktree outside the project read-only as a whole (it looks dangling in the sandbox); each submodule repo in the git dir (`modules/**`, `worktrees/*/modules/**`, recursively; `RepoScan.FindModuleRepos`) gets the same `ProtectGitDir` mounts, as does each dir between the git dir and it (so none can be moved aside and a forged repo put in its place), and one that's a symlink or has a `commondir` is refused; and checks `.git` at session end before running any host git. Recursive includes from config and config.worktree are protected, including worktreeConfig enabled through includes; conditional includes are followed conservatively. Writable symlink paths for includes are refused. The session saves the module repos there at start (`modules`); the end check quarantines any others (and repos nested in them, and a `commondir` in a kept one), and only the kept ones' checkouts are the project's own. `pen sign` keeps the ones there now. An entry whose name isn't valid UTF-8 can't be looked inside (`Native.ListUndecodable`): a directory, symlink or unknown type in the tree, or anything in `modules`/`worktrees`, is refused at start and is "couldn't check" at the end. The single-file mounts (except a linked worktree's `HEAD`/`index`) are `Mount.Verify`: `ProtectedFiles` saves them to `protected/` in the session dir with a manifest, refusing a file that isn't regular or is over 1 MB, and a session started alongside another takes that one's copies as its baseline. First in the session-end check, it compares them byte for byte: a changed file is copied to `….pen-quarantine` and written back in place (another session's mount pins the inode), anything else there is renamed aside and the file recreated. If that can't complete, the session's files stay (the session stays open, so the next session start, `pen sign` or `pen reset` retries, and new sessions are refused until it works; `GitCheck.KeptCopiesAdvice` prints the way out); once it does, the copies are deleted. `RepoGuard` reads files directly and never runs git — keep it that way, since the agent may have planted git config/hooks.

**GitHub**: supply a read-only fine-grained PAT per owner from `[github]` in user `config.toml`, chosen by `origin` owner (`GitHub.cs`). pen passes credentials through without checking or reducing their permissions; write-capable credentials allow GitHub writes. `pen sign` (`Sign.cs`) re-creates unpushed commits on the host with the user's signature.

**Config** (`Config.cs`): `~/.config/pen/` and a project's `.pen/` each hold a `config.toml` (TOML via Tomlyn). Parsing validates the TOML syntax tree first (`SyntaxParser.Parse(…, validate: true)`, errors with line numbers), then reads the untyped `TomlTable` through the source-generated `TomlContext` (never reflection-based `TomlSerializer` overloads: AOT) and applies pen's own key checks. User `config.toml` (secrets allowed): `allow`, `[github]` tokens per owner, `[env]`. Project `.pen/config.toml`: `allow`, `github_owner`, `docker`, `ports` (merged with `--port` by `Port.Merge`, each remembering whether the flag asked for it) — no secrets. Keys belong to one file or the other, except `allow`, whose lists are appended (defaults, user, project); if a key ever becomes valid in both, the convention is project scalars override and lists append. `pen allow` edits the `allow` array in place (`ConfigEdit`: insertions at syntax-tree offsets, then a re-parse that must show only the new domains added, written via temp file + rename keeping the mode). A pre-TOML `config` file in either dir is an error, not silently ignored. An optional `.pen/Dockerfile` builds a per-project image `FROM pen:latest`, tagged `<key>:latest` in the main checkout and `<key>-<hash(dir)>:latest` in a linked worktree (`Image.ProjectLayerName`).

**Home seed** (`image/sync-seed.sh`): seed-managed files overwrite sandbox copies on every start regardless of mtime. Files absent from the seed remain in the home volume; removing a seed file stops managing it without deleting the sandbox copy. Known credential paths and `.docker/` are excluded. Claude's mixed `.claude.json` takes only the seed's entire `mcpServers` map, preserving every other local field. `image/docker-proxy.sh` configures session proxy settings separately. See docs/usage.md for the ownership inventory.

## Conventions

- Verifying a change: after each change, build, unit tests and the smoke sections it touches (`SMOKE_ONLY`); the full smoke suite before finishing a larger piece of work.

- Code must stay AOT/trim-safe (`PublishAot`, `IsAotCompatible`): no reflection-based JSON serialization etc. Native calls live in `Native.cs`.
- Tests access internals via `InternalsVisibleTo`; use the `TempDir` and `Git` helpers in `Pen.Tests`.
- Keep architecture comments tied to current invariants or documentation, rather than the removed historical architecture plan.
